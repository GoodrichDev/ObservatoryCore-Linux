# BioInsights notification routing

The installed BioInsights 1.3.444.1052 `NotificationSettings` model has eleven categories, each with `Popup`, `Voice`, and `Plugin` switches. `NotificationOptions` defaults are `true`, `true`, and `false`, respectively. Its rendering bitmask is popup 1, voice 2, plugin 4; multiple applicable categories OR those bits.

The Rust worker now uses those fields instead of the former port-only `NotifyPredictions` and `NotifySamples` switches. The port-only `OverlayEnabled` switch and persistent `BISampler` bitmap have been removed. The installed plugin uses `DistanceNotifier` to emit its minimum-distance notification, alongside its actual StellarOverlay radar commands and FSS/DSS bitmap options.

Body-interest notifications combine PersonalCodex, Marked, HighValue, and NewGalactic conditions. The other source categories cover atmospheric landables, atmospheric/non-atmospheric landables with biology, confirmed species, partial/complete sample collection, minimum distance, and changes to a body's radiant star. Zero value thresholds disable high-value conditions. Species confirmation is once per system/body/species; distance guidance is armed by each partial sample and checks every recorded sample location. Replay and cached/support scans update data without emitting these notifications.

The native host follows `ObservatoryCore/PluginManagement/PluginCore.cs` and `PluginEventHandler.cs`: a plugin bit delivers to ordinary notification subscribers, while popup/audio override subscribers receive their selected native channel even when the plugin bit is clear. Native popup/voice settings and installed overrides still apply. Notification channel selection is carried as a rendering mask, never reconstructed from message wording.

Evidence comes from the user's installed assembly (hash recorded in PROVENANCE.md), its decoded `NotificationSettings.cs`, `EDJP.Observatory/NotificationOptions.cs`, `BioInsights.cs` (`SendScanNotification`, sample/body/radiant branches), and `DistanceNotifier.cs`, plus the original Core source in this repository. Tests cover all eleven category masks, aggregation, batch/support suppression, source sample/confirmation/distance text and state transitions, and native host routing to ordinary versus overriding Lua subscribers. Device audio and desktop notification presentation remain separate graphical/device acceptance checks.
